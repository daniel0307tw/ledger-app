# Clarify Session — 2026-08-23 21:00

## 議題

`tests/features/transactions/新增收支紀錄.feature` 的 Rule「交易所屬分類的收支類型必須與交易本身的類型相符」是否需要在後端 service 層強制驗證，或僅靠前端 UI 過濾即可。

## 決策

**由使用者明確授權 AI 判斷**（原話：「不知道 這由你來判斷」）。

**判斷結果：後端強制驗證。**

理由：本專案既有慣例中，CATEGORY_NOT_FOUND、ACCOUNT_NOT_FOUND 等驗證規則皆在 service 層強制執行，不只是前端 UI 過濾掉不合法選項。若只靠前端過濾，任何繞過前端（直接呼叫 API、未來第三方整合等）的請求都可能寫入類型不符的紀錄，與既有慣例的防禦深度不一致。

## 影響範圍

- `tests/features/transactions/新增收支紀錄.feature` — Rule 文字已更新，移除 CiC(ASM) 標記
- `tests/features/transactions/編輯收支紀錄.feature` — 既有 umbrella Rule 已引用同一驗證規則，無需額外修改
- Phase 05（Backend TDD）：此驗證需在 `TransactionService`（或對應 service 層）實作，比照既有 CATEGORY_NOT_FOUND 錯誤處理模式
