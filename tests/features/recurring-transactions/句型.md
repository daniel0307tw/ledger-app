# recurring-transactions 句型模型

## 實體概述

- **性質**: Aggregate（recurring_transaction 表），建立/補生成時會連動產生 ledger_transaction（透過 source_recurring_transaction_id 關聯）
- **攜帶狀態**: frequency(每天/每週/每月/每季/每年/每三年), amount, category_id, account_id, type, note, start_date, generate_count, status(啟用/停用)
- **Invariant 清單**: amount > 0；generate_count 為正整數
- **關鍵推導**：建立/補生成的副作用是產生多筆 ledger_transaction（1 個操作對應 N 筆交易），既有 domain 的 Creation 操作僅產生 1 筆，這是本輪新變異點（見系統抽象.md）

## 操作清單

| 操作 | 行為分類 | When 參數 | Then 內容 | Violation Types |
|------|---------|---------|---------|-----------------|
| 建立固定收支規則 | Creation | frequency, amount, category_id, account_id, type, note?, start_date, generate_count | 建立的規則 + N 筆生成的交易 | 金額非正數、期數非正整數、帳戶/分類不存在 |
| 編輯固定收支規則 | Mutation | id, frequency, amount, category_id, account_id, type, note?, start_date, generate_count | 更新後的規則 | 規則不存在 |
| 刪除固定收支規則 | Mutation | id | （無，已生成交易保留） | 規則不存在 |
| 查詢固定收支規則列表 | Query | （無） | 規則列表 | （無） |
| 補生成固定收支交易 | Mutation | id | 本次補生成筆數 + 交易列表 | 規則不存在、規則已停用 |

## 測試分析

### 建立固定收支規則

**等價類劃分**: 頻率（每天/每週/每月/每季/每年/每三年，各自的下一期日期推算邏輯不同）；金額（正數 / 非正數）；期數（正整數 / 非正整數）
**邊界值分析**: generate_count=1（只生成 1 筆）
**組合覆蓋**: 每月頻率 + generate_count=3 → 驗證 3 筆交易日期依序遞增 1 個月

### 補生成固定收支交易

**等價類劃分**: 已生成期數 vs 設定期數（已生成 < 設定 → 補差額；已生成 = 設定 → 補 0 筆）；規則狀態（啟用可補 / 停用不可補）
**邊界值分析**: 差額剛好為 0（不需補）

**Examples 規劃**：

| # | Feature | 驗證目標 | 前置 | 輸入 | 預期結果 |
|---|---------|---------|------|------|---------|
| 1 | 建立固定收支規則 | 每月頻率建立 3 期，生成 3 筆遞增交易 | 帳戶「永豐銀行」id=1；分類「居家」id=6 | frequency=每月, amount=15000, category=居家, account=永豐銀行, type=支出, start_date=2026-09-05, generate_count=3 | 成功，生成 3 筆交易：2026-09-05/2026-10-05/2026-11-05，各 15000 支出 |
| 2 | 建立固定收支規則 | 金額非正數 → 失敗 | 帳戶「永豐銀行」id=1；分類「居家」id=6 | amount=0（其餘同上） | 失敗，錯誤為"金額必須為正數" |
| 3 | 編輯固定收支規則 | 編輯金額不影響已生成交易 | 規則 id=1（月租 15000，已生成 3 筆各 15000） | 規則 1 金額改為 16000 | 成功，已生成的 3 筆交易金額仍為 15000 |
| 4 | 刪除固定收支規則 | 刪除規則，已生成交易保留 | 規則 id=1（已生成 2026-09-05/2026-10-05 兩筆） | 刪除規則 1 | 成功，2026-09-05/2026-10-05 兩筆交易仍存在 |
| 5 | 查詢固定收支規則列表 | 列出啟用與停用的規則 | 規則 1（啟用）、規則 2（停用） | （無） | 成功，清單含規則 1、規則 2 |
| 6 | 補生成固定收支交易 | 已生成 3 期、設定 5 期 → 補 2 期 | 規則 id=1（frequency=每月, start_date=2026-06-05, generate_count=5）已生成 2026-06-05/07-05/08-05 三筆 | 對規則 1 補生成 | 成功，本次補生成 2 筆：2026-09-05、2026-10-05 |
| 7 | 補生成固定收支交易 | 已生成期數已達設定值 → 補 0 筆 | 規則 id=1（generate_count=3）已生成 3 筆 | 對規則 1 補生成 | 成功，本次補生成 0 筆 |
| 8 | 補生成固定收支交易 | 規則已停用 → 不生成（成功，0 筆） | 規則 id=2（status=停用, generate_count=5）已生成 1 筆 | 對規則 2 補生成 | 成功，本次補生成 0 筆（停用規則不生成，非錯誤） |
