# accounts 句型模型

## 實體概述

- **性質**: Aggregate（account）；帳戶間轉帳操作同時建立 ledger_transaction 成對紀錄（見 transactions 句型模型）
- **攜帶狀態**: id, name, type(一般帳戶/信用卡)；balance 為查詢時的衍生欄位（非儲存狀態，計算方式見下）
- **Invariant 清單**: 無（名稱不強制唯一）；type 必須為 一般帳戶/信用卡 其一，且為必要參數
- **balance 計算公式**: `SUM(該帳戶所有收支紀錄中 type=收入 的 amount) - SUM(type=支出 的 amount)`，含轉帳產生的紀錄在內；一般帳戶與信用卡帳戶使用同一公式，不需特殊分支（信用卡消費記為支出，公式自然得出負數代表未繳金額）

## 操作清單

| 操作 | 行為分類 | When Data Table 欄位 | Then Data Table 欄位 | Violation Types |
|------|---------|---------------------|---------------------|-----------------|
| 建立帳戶 | Creation | name, type | id, name, type | MISSING_FIELD |
| 查詢帳戶列表 | Query | （無） | id, name, type, balance | （無） |
| 帳戶間轉帳 | Creation | from_account, to_account, amount, date | 轉出紀錄 + 轉入紀錄（各含 account, amount, is_transfer, transfer_group_id） | ACCOUNT_NOT_FOUND, SAME_ACCOUNT, INVALID_AMOUNT |

## 測試分析

### 建立帳戶

**等價類劃分**: 名稱提供 vs 未提供；type 提供 vs 未提供
**邊界值分析**: 不適用（自由字串，無長度限制規格）
**狀態轉移**: 不適用
**組合覆蓋**: 不適用
**錯誤推測**: 不適用（名稱不強制唯一，無重複衝突需要驗證；type 若提供不合法值屬 schema 層驗證，比照 category.type 慣例不在 BDD 層另立 Rule）

**Examples 規劃**：

| # | 驗證目標 | 額外前置狀態 | 輸入資料摘要 | 預期結果 | 分析維度 |
|---|---------|-------------|-------------|---------|---------|
| 1 | 缺少帳戶名稱時操作失敗 | （無） | name 缺漏, type="一般帳戶" | 失敗(MISSING_FIELD) | 等價類 |
| 2 | 缺少帳戶類型時操作失敗 | （無） | name="永豐銀行", type 缺漏 | 失敗(MISSING_FIELD) | 等價類 |
| 3 | 建立後應新增一個帳戶 | （無） | name="永豐銀行", type="一般帳戶" | 成功，帳戶已建立 | 等價類 |

### 查詢帳戶列表

**等價類劃分**: 已有多筆帳戶；一般帳戶 vs 信用卡帳戶
**邊界值分析**: 不適用
**狀態轉移**: 不適用
**組合覆蓋**: type × balance 正負號（一般帳戶通常為正、信用卡因消費計為支出通常為負）
**錯誤推測**: 不適用

**Examples 規劃**：

| # | 驗證目標 | 額外前置狀態 | 輸入資料摘要 | 預期結果 | 分析維度 |
|---|---------|-------------|-------------|---------|---------|
| 1 | 查詢結果應包含所有已建立的帳戶 | 帳戶「永豐銀行」「新光銀行」（皆一般帳戶）已存在，皆無收支紀錄 | （無） | 成功，結果含 2 筆帳戶，balance 皆為 0 | 等價類 |
| 2 | 一般帳戶餘額應正確反映收支紀錄加總（含轉帳） | 帳戶「永豐銀行」「新光銀行」（皆一般帳戶）已存在；永豐銀行有一筆收入 5000、一筆支出 2000；永豐銀行轉帳 1000 至新光銀行 | （無） | 成功，永豐銀行 balance=2000（5000-2000-1000），新光銀行 balance=1000 | 組合覆蓋 |
| 3 | 信用卡帳戶因消費計為支出，餘額顯示為負數代表未繳金額 | 帳戶「中國信託」（信用卡）已存在，有一筆支出 3000 | （無） | 成功，中國信託 balance=-3000 | 組合覆蓋 |

### 帳戶間轉帳

**等價類劃分**: 轉出帳戶不存在 / 轉入帳戶不存在 / 兩者皆存在但相同 / 金額非正數 / 正常案例
**邊界值分析**: amount = 0
**狀態轉移**: 不適用
**組合覆蓋**: 不適用
**錯誤推測**: 轉出與轉入指定同一個帳戶

**Examples 規劃**：

| # | 驗證目標 | 額外前置狀態 | 輸入資料摘要 | 預期結果 | 分析維度 |
|---|---------|-------------|-------------|---------|---------|
| 1 | 轉出或轉入帳戶不存在時操作失敗 | 僅其中一方帳戶存在 | 依序缺轉出方/轉入方 | 失敗(ACCOUNT_NOT_FOUND) | 等價類 |
| 2 | 轉出轉入帳戶相同時操作失敗 | 帳戶「永豐銀行」已存在 | from=to="永豐銀行" | 失敗(SAME_ACCOUNT) | 錯誤推測 |
| 3 | 金額為 0 時操作失敗 | 帳戶「永豐銀行」「新光銀行」已存在 | amount=0 | 失敗(INVALID_AMOUNT) | 邊界值 |
| 4 | 轉帳後應建立一筆轉出紀錄與一筆轉入紀錄，皆標記為轉帳 | 帳戶「永豐銀行」「新光銀行」已存在 | from="永豐銀行", to="新光銀行", amount=2000 | 成功，兩筆 is_transfer=true 且共用同一個 transfer_group_id | 等價類 |
